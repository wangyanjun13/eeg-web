# EEG-Web系统真实性能数据收集与使用指南

## 概述

本文档介绍了EEG-Web系统性能数据收集的实现方式，以及如何从模拟数据逐步过渡到真实数据。我们已经实现了一个智能的性能数据收集系统，它能够：

1. 优先使用系统实际运行时产生的真实性能数据
2. 在没有足够真实数据的情况下，基于当前硬件配置生成合理的模拟数据
3. 随着系统的使用，逐渐积累更多的真实数据，减少对模拟数据的依赖

## 已实现的功能

我们对系统进行了以下增强：

1. **系统监控中间件**：自动记录请求次数、响应时间和API访问模式
2. **实际硬件信息收集**：捕获真实的CPU、内存和系统配置信息
3. **Redis缓存访问**：从缓存中提取真实的处理时间和性能数据
4. **日志文件分析**：从日志中提取性能相关的信息
5. **真实EEG数据分析**：当有实际EEG数据文件时，使用它进行真实分析
6. **数据混合机制**：智能地组合真实数据和模拟数据
7. **性能数据持久化**：将收集到的性能数据保存到日志文件中，以便后续使用

## 如何使用

### 1. 启动系统

确保EEG-Web后端系统正常运行：

```bash
cd eeg-web/backend
uvicorn app.main:app --reload
```

### 2. 测试真实数据API

运行测试脚本，检查API返回的数据是否包含真实数据：

```bash
cd eeg-web
python test/test_real_data_api.py
```

测试脚本会：
- 检查所有性能API端点
- 分析返回的数据源类型
- 生成数据源分布图表
- 提供改进建议

### 3. 使用测试套件生成可视化

运行完整的测试套件：

```bash
cd eeg-web
python test/run_all_tests.py
```

测试套件会：
- 从API收集性能数据
- 生成各种性能可视化图表
- 保存结果到`eeg-web/results`目录

## 数据来源说明

系统使用以下数据来源（按优先级排序）：

1. **Redis缓存**：存储实际处理操作的性能数据
2. **日志文件**：包含系统运行时记录的性能信息
3. **实际EEG文件**：用于执行真实分析，测量实际性能
4. **硬件信息**：基于当前硬件配置估算性能指标
5. **API使用记录**：记录的请求和响应时间
6. **模拟数据**：在没有足够真实数据时的后备方案

## 如何增加真实数据比例

要使系统使用更多真实数据，可以：

1. **增加系统使用**：执行更多的数据处理和分析操作
2. **确保日志记录**：检查日志目录是否正确创建
3. **导入真实EEG数据**：将EEG数据文件放入系统数据目录
4. **执行并发负载测试**：生成真实的并发性能数据
5. **长时间运行系统**：收集更多资源使用数据

## 系统中的模拟数据

虽然系统会优先使用真实数据，但在以下情况下仍会使用模拟数据：

1. **系统刚刚部署**：尚未收集到足够的性能数据
2. **特定操作很少执行**：某些不常用功能没有足够的样本
3. **无法直接测量**：某些指标无法在当前环境下直接获取

模拟数据设计基于：
- 真实硬件规格和性能特性
- EEG数据处理的典型资源需求
- 合理的性能模型和变异性

## 结论

我们的实现方案平衡了准确性和可用性，即使在缺乏全面真实数据的情况下，也能提供合理的性能评估。随着系统使用的增加，模拟数据会逐渐被真实数据替代，使性能评估越来越准确。
